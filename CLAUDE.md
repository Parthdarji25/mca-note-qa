# MCA Notes — project spec for Claude Code

A free, static study website of **questions and answers** for three MCA subjects, hosted on **GitHub Pages**. GitHub is the only backend: every chapter's Q&A is one `.md` or `.html` file in this repo, and an admin area in the browser edits those files through the GitHub REST API (commit + push).

Read this whole file before starting any task. Follow it unless the user says otherwise.

---

## 1. Tech stack (no build step)

- Plain **HTML5 + CSS3 + vanilla JavaScript (ES modules)**. No framework, no bundler, no npm runtime dependencies.
- Third-party libraries loaded from a CDN (cdnjs or jsDelivr) with a **pinned exact version**:
  - **marked** — Markdown → HTML
  - **DOMPurify** — sanitise every piece of HTML before it is put on the page
  - **JSZip** — build the "Download all (.zip)" file in the browser
- Fonts from Google Fonts: **Space Grotesk** (headings, 500/600/700), **IBM Plex Sans** (body, 400/500/600), **IBM Plex Mono** (numbers, paths, code, 400/500).
- Hosting: GitHub Pages, branch `main`, folder `/` (root). A `.nojekyll` file at the root is **required** so `.md` files are served raw and not processed by Jekyll.
- Pages use query strings for routing (GitHub Pages has no server routing):
  - `subject.html?s=information-security`
  - `chapter.html?s=information-security&ch=02`
- Local preview must be served over http (fetch does not work on `file://`): `python3 -m http.server 8000` or the VS Code Live Server extension.

## 3. Naming convention (must be followed everywhere)

```
qa/sem-<N>/<subject-slug>/ch<NN>-<chapter-slug>.md      (or .html)
qa/sem-<N>/<subject-slug>/images/ch<NN>-<image-name>.png
```

- Lowercase; words joined with single hyphens.
- Chapter number is always two digits: `ch01` … `ch14`.
- `slugify(text)`: lowercase → `&` becomes `and` → every run of characters that are not `a-z0-9` becomes `-` → trim leading/trailing `-`.
  - "Authentication – I" → `authentication-i`
  - "Distributed Systems & Cloud Computing" → `distributed-systems-cloud-computing`
- Exactly **one** Q&A file per chapter, either `.md` or `.html`, never both.
- The path is always generated by code from semester + subject + chapter number + title. The admin never types a path.

Subject slugs:
- `sem-2/information-security`
- `sem-3/distributed-systems-cloud-computing`
- `sem-3/ethical-hacking`

## 5. Q&A file format

### Markdown (.md)

```md
## Q1. What is cryptography? Explain its goals.
Marks: 5

Answer in Markdown…

## Q2. Differentiate between symmetric and asymmetric cryptography.
Marks: 10

| Point | Symmetric | Asymmetric |
|---|---|---|
| Keys | One shared key | Public + private pair |

> **Remember:** symmetric uses the same key both ways.
```

- A question starts at a line matching `^## Q(\d+)\.\s+(.+)$`.
- The next non-empty line must match `^Marks:\s*(5|10)\s*$`.
- Everything after that line, up to the next question heading, is the answer.
- Supported inside answers:
  - `###` sub-headings
  - bold, italic, inline code
  - bullet and numbered lists
  - tables
  - fenced code blocks
  - images, with paths relative to the chapter file
  - links
- A blockquote whose text starts with `**Remember:**` is rendered as the highlighted note box.

### HTML (.html)

```html
<section class="question" data-marks="5">
  <h2>What is cryptography? Explain its goals.</h2>
  <div class="answer">
    <p>…</p>
  </div>
</section>
```

- Parse the file with `DOMParser`. Each `section.question` is one question; `data-marks` must be 5 or 10.
- The first `h2` is the question text; `.answer` holds the answer.
- `blockquote.note` is the Remember box.
- Allowed tags in answers:
  - `p h3 h4 strong em b i u br`
  - `ul ol li`
  - `table thead tbody tr th td`
  - `pre code blockquote`
  - `img a sup sub hr`
- Strip everything else: `script`, `style`, `iframe`, `form`, inline `style`, every `on*` attribute, and `javascript:` URLs. Use DOMPurify with an explicit allow-list.

### Shared rules

- Marks are only **5 or 10** (there is no 2-mark category anywhere in the site).
- Number questions Q1, Q2, Q3… in order. The parser renumbers by order of appearance and the admin editor warns about gaps.
- Resolve image `src` relative to the chapter file's folder.
- External links open in a new tab with `rel="noopener noreferrer"`.
- **Never** insert unsanitised HTML into the DOM, whether it came from Markdown or from HTML.

## 7. Admin area (`/admin/`)

The admin area uses a dark header, a yellow "ADMIN" badge (`#FCD34D`), and the repo + branch in mono.

Every admin page has the same footer:
- Format guides: Markdown (.md) syntax · HTML (.html) syntax · File naming rules · Download templates
- right side: repo name · Open repository

### Auth (admin/index.html)

- Fields:
  - Repository (`owner/repo`)
  - Branch (`main`)
  - Personal access token (password field)
  - "Keep me signed in": Until I close this tab (sessionStorage, the default) / On this device (localStorage)
- Validate with `GET /repos/{owner}/{repo}`. Show a clear error on 401/403/404.
- Side panel with the steps to create a **fine-grained token**:
  - this repo only
  - Contents: Read and write
  - with an expiry date
- Never log the token, never put it in a URL, never commit it.
- Add `<meta name="robots" content="noindex">` to every admin page.

### GitHub client (assets/js/admin/github.js)

- Base URL `https://api.github.com`.
- Headers:
  - `Authorization: Bearer <token>`
  - `Accept: application/vnd.github+json`
  - `X-GitHub-Api-Version: 2022-11-28`
- Read a file: `GET /repos/{o}/{r}/contents/{path}?ref={branch}`. Decode base64 as UTF-8 with `TextDecoder`.
- **Every save must be one atomic commit** that changes the Q&A file and `data/subjects.json` together. Use the Git Data API:
  1. `GET /git/ref/heads/{branch}` → latest commit sha
  2. `GET /git/commits/{sha}` → base tree sha
  3. `POST /git/blobs` for each new or changed file (base64 content)
  4. `POST /git/trees` with `base_tree` and the entries
     - to delete a file, add an entry with `"sha": null`
     - when switching `.md` ↔ `.html`, delete the old file in the same tree
  5. `POST /git/commits` with message, tree and parents
  6. `PATCH /git/refs/heads/{branch}` with the new sha
- If the PATCH fails because the branch moved (422 or 409): re-fetch, rebuild the change on top, and retry once. Then show "Someone else pushed; reload".
- Commit messages:
  - `Add Q&A: <subject-id> ch<NN>`
  - `Update Q&A: <subject-id> ch<NN>`
  - `Upload Q&A (html): <subject-id> ch<NN>`
  - `Delete Q&A: <subject-id> ch<NN>`
  - `Add image: <subject-id> ch<NN>-<name>`
- After a commit, show the green "Pushed to main · <short sha> · <message> · The live site updates in about a minute" banner with a "View Q&A page" link.

### admin/chapters.html

- Subject tabs.
- Table columns: No. · Chapter · File · Last change · Actions.
- Actions:
  - **Edit** + **Delete** when the file exists
  - **Create file** when it doesn't
- "Add chapter" button.
- Delete opens a modal showing the full path, an editable commit message, Cancel, and a red "Delete and commit". Deleting also sets `file: null` and `questions: 0` in subjects.json in the same commit.
- Side column:
  - "Recent commits": the last 5 from `GET /repos/{o}/{r}/commits?path=qa`
  - a "File naming" card with the rules from section 3

### admin/editor.html (?s=<subject>&ch=<NN>)

- Chapter details: Semester, Subject, Module/Unit, Chapter no., Chapter title.
- A "Saves to qa/sem-2/…/ch02-cryptography.md" line that updates live as the fields change.
- Mode switch: **Write questions** | **Upload .html file**.
  - **Write questions:** one card per question with:
    - question input
    - Marks select (5 / 10 only)
    - answer textarea (Markdown)
    - move up / move down / delete buttons

    Plus an "Add question" button. Saving serialises the cards to the Markdown format from section 5.
  - **Upload .html file:**
    - drop zone with a file input (`.html,.htm`)
    - a line with the file name, size, and how many questions were found
    - a warning listing anything that will be stripped
    - a sanitised preview rendered with the site styles
- Image upload goes to `images/ch<NN>-<slug-of-filename>.<ext>`.
- Commit panel: message, "Files changed" list (A/M/D + path), "Commit and push to main", "Discard changes".
- Validation before commit: at least one question, every question has text and an answer, marks are 5 or 10.

### admin/guide.html

- Markdown | HTML tabs. Each tab shows:
  - a complete example file in a dark code panel
  - a syntax reference table: Element · You write · Notes
- The HTML tab also shows a "Removed from .html files" box.
- Sections with ids `#naming` (rules) and `#templates` (download `templates/qa-template.md` and `.html`).

## 9. Working rules for Claude Code

- Work one phase at a time, as the user asks. Don't build later phases early.
- Before each commit:
  - serve the site locally
  - check the pages you changed load with no console errors
  - check that existing pages still work
- Commit with a clear message (`feat: …`, `fix: …`, `chore: …`, `docs: …`) and then `git push origin main`.
- Show the user the commit hash and what changed.
- Don't add libraries beyond marked, DOMPurify and JSZip without asking.
- Never commit secrets, tokens or `.env` files. Keep `.gitignore` up to date.
- Keep code readable: small modules, JSDoc on exported functions, no minified code in the repo.
