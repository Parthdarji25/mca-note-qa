# MCA Notes — project spec for Claude Code

A free, static study website of **questions and answers** for three MCA subjects, hosted on **GitHub Pages**. GitHub is the only backend: each subject's questions are one `.md` or `.html` file in this repo, and an admin area in the browser edits that file through the GitHub REST API (commit + push).

There is **no chapter structure**. A subject is one flat list of questions. Chapter and year are optional tags on a question, used only for filtering.

Read this whole file before starting any task. Follow it unless the user says otherwise.

---

## 1. Tech stack (no build step)

- Plain **HTML5 + CSS3 + vanilla JavaScript (ES modules)**. No framework, no bundler, no npm runtime dependencies.
- Third-party libraries loaded from a CDN (cdnjs or jsDelivr) with a **pinned exact version**:
  - **marked** — Markdown → HTML
  - **DOMPurify** — sanitise every piece of HTML before it is put on the page
  - **JSZip** — build the "Download all (.zip)" file in the browser
- Fonts from Google Fonts: **Space Grotesk** (headings, 500/600/700), **IBM Plex Sans** (body, 400/500/600), **IBM Plex Mono** (numbers, paths, code, 400/500).
- Hosting: GitHub Pages, branch `main`, folder `/` (root). A `.nojekyll` file at the root is **required** so `.md` files are served raw and not processed by Jekyll.
- Pages use query strings for routing (GitHub Pages has no server routing):
  - `subject.html?s=information-security`
  - `subject.html?s=information-security&marks=10&year=2025&chapter=Cryptography&q=text` (all filters optional, kept in the URL so a filtered view can be shared)
- Local preview must be served over http (fetch does not work on `file://`): `python3 -m http.server 8000` or the VS Code Live Server extension.

## 3. Naming convention (must be followed everywhere)

```
qa/sem-<N>/<subject-slug>/questions.md      (or questions.html)
qa/sem-<N>/<subject-slug>/images/<image-name>.<ext>
```

- Lowercase; words joined with single hyphens.
- `slugify(text)`: lowercase → `&` becomes `and` → every run of characters that are not `a-z0-9` becomes `-` → trim leading/trailing `-`.
  - "Distributed Systems & Cloud Computing" → `distributed-systems-cloud-computing`
  - Image names are the slug of the uploaded file name (without its extension).
- Exactly **one** Q&A file per subject, either `.md` or `.html`, never both. Saving from an `.html` file writes `questions.md` and deletes the `.html` in the same commit.
- The path is always generated by code from semester + subject. The admin never types a path.

Subject slugs:
- `sem-2/information-security`
- `sem-3/distributed-systems-cloud-computing`
- `sem-3/ethical-hacking`

## 4. Subjects (source of truth for data/subjects.json)

- **Information Security** — Semester 2 (accent `#2448C8`, tint `#E8EDFB`, dark `#16308F`)
- **Distributed Systems and Cloud Computing** — Semester 3 (accent `#0B6B63`, tint `#E1F1EE`, dark `#08504A`)
- **Ethical Hacking** — Semester 3 (accent `#B4410B`, tint `#FBEADF`, dark `#8A3108`)

There are no modules, units or chapters in the data. Chapter names are free-text tags on questions.

### data/subjects.json shape

```json
{
  "subjects": [
    {
      "id": "information-security",
      "name": "Information Security",
      "semester": 2,
      "folder": "qa/sem-2/information-security",
      "color": { "accent": "#2448C8", "tint": "#E8EDFB", "dark": "#16308F" },
      "file": "questions.md",
      "questions": 7
    }
  ]
}
```

- `file` is `null` while a subject has no questions yet; the UI then shows "Coming soon".
- `questions` is the question count. The admin updates both fields on every save.

## 5. Q&A file format

### Markdown (.md)

```md
## Q1. What is cryptography? Explain its goals.
Marks: 5
Chapter: Cryptography
Years: 2024, 2025

Answer in Markdown…

## Q2. Differentiate between symmetric and asymmetric cryptography.
Marks: 10

| Point | Symmetric | Asymmetric |
|---|---|---|
| Keys | One shared key | Public + private pair |

> **Remember:** symmetric uses the same key both ways.
```

- A question starts at a line matching `^## Q(\d+)\.\s+(.+)$`.
- The next non-empty line must match `^Marks:\s*(5|10)\s*$`.
- Optional tag lines may follow directly under the marks line, with no blank line between, in either order:
  - `Chapter: Cryptography` — a free-text label (up to 80 characters)
  - `Years: 2024, 2025` — four-digit years from 2000 to 2100, separated by commas
- Everything after that (from the first blank line), up to the next question heading, is the answer.
- Supported inside answers:
  - `###` sub-headings
  - bold, italic, inline code
  - bullet and numbered lists
  - tables
  - fenced code blocks
  - images, with paths relative to the Q&A file's folder
  - links
- A blockquote whose text starts with `**Remember:**` is rendered as the highlighted note box.

### HTML (.html)

```html
<section class="question" data-marks="5" data-chapter="Cryptography" data-years="2024,2025">
  <h2>What is cryptography? Explain its goals.</h2>
  <div class="answer">
    <p>…</p>
  </div>
</section>
```

- Parse the file with `DOMParser`. Each `section.question` is one question; `data-marks` must be 5 or 10. `data-chapter` and `data-years` (comma-separated) are optional.
- The first `h2` is the question text; `.answer` holds the answer.
- `blockquote.note` is the Remember box.
- Allowed tags in answers:
  - `p h3 h4 strong em b i u br`
  - `ul ol li`
  - `table thead tbody tr th td`
  - `pre code blockquote`
  - `img a sup sub hr`
- Strip everything else: `script`, `style`, `iframe`, `form`, inline `style`, every `on*` attribute, and `javascript:` URLs. Use DOMPurify with an explicit allow-list.

### Shared rules

- Marks are only **5 or 10** (there is no 2-mark category anywhere in the site).
- Number questions Q1, Q2, Q3… in order. The parser renumbers by order of appearance; the admin editor writes them in order.
- Years are unique and stored ascending. Invalid years are ignored with a warning.
- Resolve image `src` relative to the Q&A file's folder.
- External links open in a new tab with `rel="noopener noreferrer"`.
- **Never** insert unsanitised HTML into the DOM, whether it came from Markdown or from HTML.

## 6. Public pages

All pages share a header: logo mark ("#" in a dark rounded square) + "MCA Notes", nav, search. Under 640px the nav collapses behind a menu button.

The footer has: "made by [YOUR NAME]" · "Hosted free on GitHub Pages" · Edit on GitHub · Admin.

### index.html
- Hero:
  - Eyebrow: "MCA · Semester 2 & 3 · Free and open"
  - H1: "Questions & answers, subject by subject."
  - Buttons: Browse subjects, View on GitHub
- "Continue practising" card for the last subject opened, read from localStorage.
- Subjects section with an All / Semester 2 / Semester 3 filter.
- Three subject cards, each with:
  - an accent strip and a semester chip
  - the subject name
  - "7 questions" (or "No questions yet")

  - a progress bar ("3 of 7 seen")
  - an "Open subject" button
- Dark "How the site works" section: three steps plus a folder tree.

### subject.html (Q&A reader)
- There is **no chapter list and no separate notes section**. A subject is one list of questions.
- Accent-coloured hero with breadcrumb, subject name, "Semester 2 · 7 questions · 5 marks × 4 · 10 marks × 3", a "2 of 7 seen" progress bar and a "Q&A folder on GitHub" button.
- Toolbar:
  - filter chips **All / 5 marks / 10 marks**, and Expand all / Collapse all
  - **Year asked** and **Chapter** selects, shown only when some question has that tag (with a "No year tagged" / "No chapter tag" choice when tagged and untagged questions are mixed)
  - result count and a "Clear filters" button
  - the header search box filters by question text, tags and answer text
- **No practice mode.**
- Question card:
  - "Q1" mono badge
  - question in Space Grotesk 21px
  - "5 marks" caption, the chapter tag (accent-tint pill) and year tags (outlined pills)
  - answer at 17px, line-height 1.75, max 70ch
  - a "Show answer / Hide answer" button with `aria-expanded`
- The first two answers are open by default (or the one in a `#q5` link).
- Side column: "Your progress" card (questions seen, no reset button); "Jump to" grid of question numbers (seen ones tinted); "Resources" card with **only** a "Download all Q&A (.zip)" button (JSZip, the subject's Q&A file); "Source file" path with an "Edit on GitHub" link; "Other subjects" links.
- Progress: opening an answer marks that question as seen (stored per subject under a hash of the question text, so it survives reordering). Seen keys of questions that no longer exist are dropped.
- Responsive:
  - 900px and up: list + 320px side column
  - under 900px: one column, the side cards form a grid below the list
  - phone (under 640px): compact hero, marks chips scroll horizontally, each card is a full-width button that expands its answer, with a +/− sign

## 7. Admin area (`/admin/`)

The admin area uses a dark header, a yellow "ADMIN" badge (`#FCD34D`), and the repo + branch in mono.

Every admin page has the same footer:
- Format guides: Markdown (.md) syntax · HTML (.html) syntax · File naming rules · Download templates
- right side: repo name · Open repository

### Auth (admin/index.html)

- Fields:
  - Repository (`owner/repo`)
  - Branch (`main`)
  - Personal access token (password field)
  - "Keep me signed in": Until I close this tab (sessionStorage, the default) / On this device (localStorage)
- Validate with `GET /repos/{owner}/{repo}`. Show a clear error on 401/403/404.
- Side panel with the steps to create a **fine-grained token**:
  - this repo only
  - Contents: Read and write
  - with an expiry date
- Never log the token, never put it in a URL, never commit it.
- Add `<meta name="robots" content="noindex">` to every admin page.

### GitHub client (assets/js/admin/github.js)

- Base URL `https://api.github.com`.
- Headers:
  - `Authorization: Bearer <token>`
  - `Accept: application/vnd.github+json`
  - `X-GitHub-Api-Version: 2022-11-28`
- Read a file: `GET /repos/{o}/{r}/contents/{path}?ref={branch}`. Decode base64 as UTF-8 with `TextDecoder`.
- **Every save must be one atomic commit** that changes the subject's Q&A file and `data/subjects.json` together. Re-read both files right before committing and apply the change to those fresh copies. Use the Git Data API:
  1. `GET /git/ref/heads/{branch}` → latest commit sha
  2. `GET /git/commits/{sha}` → base tree sha
  3. `POST /git/blobs` for each new or changed file (base64 content)
  4. `POST /git/trees` with `base_tree` and the entries
     - to delete a file, add an entry with `"sha": null`
     - when switching `.md` ↔ `.html`, delete the old file in the same tree
  5. `POST /git/commits` with message, tree and parents
  6. `PATCH /git/refs/heads/{branch}` with the new sha
- If the PATCH fails because the branch moved (422 or 409): re-fetch, rebuild the change on top, and retry once. Then show "Someone else pushed; reload".
- Commit messages:
  - `Add Q&A: <subject-id> Q<N>`
  - `Update Q&A: <subject-id> Q<N>`
  - `Upload Q&A (html): <subject-id> (<n> questions)`
  - `Delete Q&A: <subject-id> Q<N>`
  - `Add image: <subject-id> <name>`
- After a commit, show the green "Pushed to main · <short sha> · <message> · The live site updates in about a minute" banner with a "View Q&A page" link.

### admin/questions.html

- Subject tabs.
- Shows the subject's file path and last change, then a search box and Marks / Year / Chapter filters.
- Table columns: No. · Question · Marks · Chapter · Years · Actions (**Edit** + **Delete**). On phones each row becomes a stacked card.
- "Add question" button.
- Delete opens a modal showing the full path, an editable commit message, Cancel, and a red "Delete and commit". Deleting renumbers the later questions and updates the count in subjects.json in the same commit. Deleting the last question deletes the file and sets `file: null` and `questions: 0`.
- Side column:
  - "Recent commits": the last 5 from `GET /repos/{o}/{r}/commits?path=qa`
  - a "File naming" card with the rules from section 3

### admin/editor.html (?s=<subject>&q=<position>)

- Details: Semester, Subject, **Chapter tag** (optional, autocompletes from tags already used), **Years asked** (optional, typed or picked from quick-pick year buttons).
- A "Saves to qa/sem-2/…/questions.md" line that updates live.
- With `q` the page edits that question (semester and subject locked); without it, it adds one. After a successful add the form clears but keeps the marks, chapter and years, for entering many questions in a row.
- Mode switch: **Write question** | **Import .html file**.
  - **Write question:** question input, Marks select (5 / 10 only), **Question no.** (position in the list; others shift), answer textarea (Markdown). Saving rewrites the subject's Markdown file.
  - **Import .html file:**
    - drop zone with a file input (`.html,.htm`)
    - a line with the file name, size, and how many questions were found
    - a warning listing anything that will be stripped
    - a sanitised preview rendered with the site styles
    - the questions are appended to the subject's list; the chapter tag and years above are applied to those that have none
- An existing `.html` file is read too; saving converts it to `questions.md` and deletes the `.html` in the same commit (answers stay as sanitised HTML inside the Markdown).
- Image upload goes to `images/<slug-of-filename>.<ext>`.
- Commit panel: message, "Files changed" list (A/M/D + path), "Commit and push to main", "Discard changes".
- Validation before commit: question text and answer present, marks 5 or 10, valid years, Question no. in range; for imports, at least one question and no parse errors.

### admin/guide.html

- Markdown | HTML tabs. Each tab shows:
  - a complete example file in a dark code panel
  - a syntax reference table: Element · You write · Notes
- The HTML tab also shows a "Removed from .html files" box.
- Sections with ids `#naming` (rules) and `#templates` (download `templates/qa-template.md` and `.html`).

- Subject accents come from subjects.json and are applied with CSS custom properties.
- Accessibility:
  - real `<button>` / `<a>` / `<label>` elements
  - touch targets of at least 44px
  - visible focus rings
  - text contrast ≥ 4.5:1
  - `aria-expanded` on answer toggles, `aria-current` on the active page
- No emoji. No gradient backgrounds. Icons are inline stroke SVGs.

## 9. Working rules for Claude Code

- Work one phase at a time, as the user asks. Don't build later phases early.
- Before each commit:
  - serve the site locally
  - check the pages you changed load with no console errors
  - check that existing pages still work
- Commit with a clear message (`feat: …`, `fix: …`, `chore: …`, `docs: …`) and then `git push origin main`.
- Show the user the commit hash and what changed.
- Don't add libraries beyond marked, DOMPurify and JSZip without asking.
- Never commit secrets, tokens or `.env` files. Keep `.gitignore` up to date.
- Keep code readable: small modules, JSDoc on exported functions, no minified code in the repo.
