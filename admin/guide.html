Format guide

Every chapter is one file, written either as Markdown or as HTML. Marks are always 5 or 10. Questions are numbered Q1, Q2, Q3 in order.

Example file

## Q1. What is cryptography? Explain its goals.
Marks: 5

**Cryptography** protects information by turning it into cipher text.

- **Confidentiality** – only authorised people can read it.
- **Integrity** – it has not been changed.

> **Remember:** the goals are C-I-A-N.

## Q2. Differentiate between symmetric and asymmetric cryptography.
Marks: 10

### Comparison

| Point | Symmetric | Asymmetric |
|---|---|---|
| Keys | One shared key | Public + private pair |
| Speed | Fast | Slow |

Removed from .html files

Uploaded files are cleaned before they are saved, and again every time a page is shown. The editor lists anything it will remove.

  • <script>, <style>, <iframe>, <form>, <object> and <embed> elements.
  • Inline style="…" attributes.
  • Every event attribute: onclick, onload, onerror and all other on… attributes.
  • javascript: links.
  • Any tag not in the table above (for example div, span, h1, h2, h5 inside an answer). The text inside is kept; the tag is dropped.
  • Classes, ids and data attributes, except class="note" on a blockquote.

File naming rules

You never type a path. The editor builds it from the semester, subject, chapter number and title:

qa/sem-<N>/<subject-slug>/ch<NN>-<chapter-slug>.md    (or .html)
qa/sem-<N>/<subject-slug>/images/ch<NN>-<image-name>.png
  • Lowercase; words joined with single hyphens.
  • The chapter number is always two digits: ch01 to ch14.
  • & becomes and. Every other run of characters that are not a-z or 0-9 becomes one hyphen. Hyphens at the ends are removed.
  • Exactly one Q&A file per chapter: .md or .html, never both. Switching format deletes the old file in the same commit.
